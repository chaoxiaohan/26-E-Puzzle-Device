# 求解期间暂停实时视觉处理（2026-10-13）

**已在鲁班猫 1 部署并完成真实摄像头验证。** 当前运行版本为 `pause-low-load-20261013`，扑克算法版本仍为 `cut-text-integrity-20261013`。界面和后端各一个进程正常运行，摄像头、串口在线。

正式开始异步求解后，实时画面和二值图保留最后一帧。取图稳定阶段继续实时检测，等待上限为两秒。等待求解期间跳过相机读取、图像转换、分割及轮廓检测、稳定碎片队列更新、预览 JPEG 编码和逐帧绘制。串口服务、控制指令、求解计时和比赛超时检查继续运行，每轮等待 50 毫秒。

求解完成、异常结束或点击停止后恢复实时视觉。任务在等待循环中途完成时，留到下一轮恢复取帧后处理结果。求解输入图像是独立快照，不受预览绘制影响。原生窗口继续处理输入事件，Flutter 使用现有图片版本缓存，无需重新构建界面。

为降低实时处理负载，主循环 OpenCV 限制为一个线程，实时处理帧率上限为 10 FPS。上限不代表实际帧率：本次现场场景约 1.7 FPS。碎片历史窗口扩展到两秒，保留低帧率下三帧中值取图要求。图像分辨率和扑克求解算法保持原有设置。

状态文件包含 `vision_paused`、`vision_processing_revision`、`vision_threads`、`vision_max_fps`。暂停期间 FPS 为 0，后端状态仍刷新。

## 实机验证

使用现场绿色背景、四块矩形纸片的真实摄像头画面。手动发起一次 CARD 求解，在暂停期间连续采样 12 次：

- 画面版本一直为 82，预览 JPEG SHA-256 始终相同；FPS 为 0，`vision_paused=true`。
- 计时从 277.5 ms 增长到 3139.9 ms，状态更新时间持续推进，串口始终在线。
- 停止本次测试求解后，`solving=false`、`vision_paused=false`，新画面版本增长到 83。
- 自动执行状态关闭，仅发送求解及停止求解指令，未发送机械臂运动命令。

短时 CPU 采样如下。视觉主循环进程按一个核心 100% 计；整机按四核合计 100% 计，两个指标不可混用。

| 状态 | 视觉主循环进程 | 整机 CPU |
| --- | ---: | ---: |
| 实时识别、未求解 | 99.48% | 65.45% |
| 求解中、视觉暂停 | 10.72% | 88.05% |

这证明视觉主循环减少了 CPU 占用；求解进程、界面及其他系统工作仍会占用 CPU。未完成同一图片的完整求解前后耗时对比，不能据此宣称总求解已缩短到某个时间。本次短时运行也不构成长时间稳定性或此前卡死原因的证明。
