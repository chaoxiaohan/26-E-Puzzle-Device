# 拼图平台串口通信协议

本文档用于树莓派端与平台执行端之间的串口通信。  
协议不包含版本号，不使用包尾。执行端只需实现：

1. 接收并缓存完整抓取动作；
2. 收到开始命令后执行已缓存动作；
3. 相对点动、绝对移动和归零；
4. 返回平台当前 X、Y、Z 和旋转角度；
5. 正确回复 `OK` 或“请求重发”。

## 1. 串口参数

- 默认波特率：`115200`
- 数据位：8
- 停止位：1
- 校验位：无
- 流控：无
- 多字节整数：小端序

树莓派界面允许选择其他波特率，执行端与树莓派设置必须一致。

## 2. 数据帧

```text
AA 55 | CMD | FLAGS | SEQ | LEN | PAYLOAD | CRC16_L | CRC16_H
```

| 字段 | 长度 | 说明 |
|---|---:|---|
| `AA 55` | 2字节 | 固定包头 |
| `CMD` | 1字节 | 命令 |
| `FLAGS` | 1字节 | 标志 |
| `SEQ` | 1字节 | 包序号，0~255循环 |
| `LEN` | 1字节 | Payload字节数，0~255 |
| `PAYLOAD` | LEN字节 | 命令数据 |
| `CRC16_L/H` | 2字节 | CRC低字节在前 |

不使用包尾。接收程序应按包头、固定头、Payload长度和CRC解析数据。

### 2.1 FLAGS

| 位 | 含义 |
|---|---|
| bit0 | 相对移动或相对旋转 |
| bit4 | 当前帧为重发帧 |
| bit5 | 要求接收端回复 |
| 其他 | 保留，发送时置0 |

### 2.2 CRC

- 算法：CRC16-CCITT-FALSE
- 多项式：`0x1021`
- 初始值：`0xFFFF`
- 不反转输入和输出
- 不进行最终异或
- 计算范围：从 `CMD` 开始，到 `PAYLOAD` 最后一个字节
- 不包含包头 `AA 55`
- CRC在线路上低字节先发送

伪代码：

```c
uint16_t crc16_ccitt(const uint8_t *data, uint16_t length)
{
    uint16_t crc = 0xFFFF;
    for (uint16_t i = 0; i < length; ++i) {
        crc ^= (uint16_t)data[i] << 8;
        for (uint8_t bit = 0; bit < 8; ++bit) {
            if (crc & 0x8000) {
                crc = (uint16_t)((crc << 1) ^ 0x1021);
            } else {
                crc <<= 1;
            }
        }
    }
    return crc;
}
```

## 3. 数据类型和单位

- `int32_t x/y/z`：平台自身坐标单位。可以是脉冲、0.01mm或其他固定单位，但所有命令和位置回复必须始终使用同一种单位。
- `int16_t rotation_cdeg`：角度的 `0.01°`，例如 `9000` 表示 `90.00°`。
- 旋转正方向：约定为从平台上方向下看逆时针为正。
- 所有结构体仅用于描述字段顺序，不允许直接发送带编译器填充的结构体；应逐字段序列化，或使用一字节对齐。

## 4. 树莓派发送的命令

### 4.1 `CMD=0x10`：缓存一个完整抓取动作

Payload固定为30字节：

```c
uint8_t task_id;
uint8_t action_index;
uint8_t action_count;
uint8_t piece_id;
int32_t pick_x;
int32_t pick_y;
int32_t pick_z;
int32_t place_x;
int32_t place_y;
int32_t place_z;
int16_t rotation_cdeg;
```

字段含义：

- `task_id`：当前拼图任务编号，0~255循环。
- `action_index`：当前动作下标，从0开始。
- `action_count`：本任务动作总数。
- `piece_id`：碎片编号。
- `pick_x/y/z`：抓取位置。
- `place_x/y/z`：放置位置。
- `rotation_cdeg`：从抓取姿态到放置姿态需要执行的旋转量。

执行端收到后：

1. 检查长度、CRC和字段范围；
2. 按 `task_id + action_index` 缓存或覆盖动作；
3. 不立即运动；
4. 回复 `0x80 OK`。

同一帧可能因超时被重发。执行端必须保证重复接收同一动作不会增加动作数量。

### 4.2 `CMD=0x11`：开始执行

Payload固定为1字节：

```c
uint8_t task_id;
```

执行端只有在以下条件均满足时才开始：

- 已收到该 `task_id` 的全部动作；
- 动作下标覆盖 `0` 到 `action_count-1`；
- 每个动作的 `action_count` 一致。

收到命令后先回复 `0x80 OK`，再按 `action_index` 从小到大执行。

同一 `task_id` 的开始命令重复到达时，不得从头重复执行；应回复OK并忽略重复启动。

### 4.3 `CMD=0x20`：平台控制或位置查询

Payload固定为15字节：

```c
uint8_t control_type;
int32_t x;
int32_t y;
int32_t z;
int16_t rotation_cdeg;
```

`control_type`：

| 值 | 功能 | 参数 |
|---:|---|---|
| `1` | 绝对移动 | X/Y/Z/角度为目标绝对值 |
| `2` | 相对移动 | X/Y/Z/角度为本次增量 |
| `3` | 平台归零 | 后续字段全部填0 |
| `4` | 查询当前位置 | 后续字段全部填0 |

对于 `control_type=1/2/3`，执行端接收成功后回复普通OK。

对于 `control_type=4`，执行端不移动，立即读取并返回当前位置，回复格式见5.2。

树莓派可能连续进行多次“移动—查询位置”操作。执行端不需要知道这些坐标
用于何种上层功能，也不需要记录查询次数；每次查询都只返回当时的真实位置。

## 5. 执行端回复

### 5.1 `CMD=0x80`：普通OK

Payload固定为1字节：

```c
uint8_t acknowledged_seq;
```

`acknowledged_seq` 必须等于被确认命令帧的 `SEQ`。

### 5.2 `CMD=0x80`：当前位置回复

仅用于回复 `CMD=0x20, control_type=4`。Payload固定为15字节：

```c
uint8_t acknowledged_seq;
int32_t current_x;
int32_t current_y;
int32_t current_z;
int16_t current_rotation_cdeg;
```

位置必须是执行端当前实际使用的坐标，而不是上一条命令的目标值。  
如果平台正在运动，推荐返回编码器或运动规划器中的实时位置。

### 5.3 `CMD=0x81`：请求重发

Payload固定为1字节：

```c
uint8_t requested_seq;
```

以下情况可以发送 `0x81`：

- CRC错误；
- Payload长度错误；
- 命令支持但字段非法；
- 缓冲区暂时无法接收该命令。

如果连包头或SEQ都无法可靠解析，可直接丢弃该数据，等待树莓派超时重发。

## 6. 超时与重发

- 树莓派发送一帧后等待回复约120ms。
- 没有收到有效回复时，最多发送3次。
- 重发帧保持原 `SEQ` 不变，并设置 `FLAGS.bit4=1`。
- 执行端应按 `CMD + SEQ` 识别短时间内的重复帧。
- 对已成功处理的重复帧，应重新发送对应回复，但不能重复执行动作。

## 7. 完整十六进制示例

### 7.1 查询当前位置

SEQ=`01`：

```text
AA 55 20 20 01 0F
04 00 00 00 00 00 00 00 00 00 00 00 00 00 00
4E D4
```

### 7.2 返回当前位置

假设：

- X=`10000`
- Y=`20000`
- Z=`3000`
- 角度=`90.00°`

回复：

```text
AA 55 80 00 01 0F
01 10 27 00 00 20 4E 00 00 B8 0B 00 00 28 23
C7 53
```

### 7.3 X轴相对移动+10

SEQ=`02`：

```text
AA 55 20 21 02 0F
02 0A 00 00 00 00 00 00 00 00 00 00 00 00 00
9B DE
```

### 7.4 平台归零

SEQ=`03`：

```text
AA 55 20 20 03 0F
03 00 00 00 00 00 00 00 00 00 00 00 00 00 00
1D 8D
```

普通OK：

```text
AA 55 80 00 03 01 03 DE 69
```

请求重发：

```text
AA 55 81 00 03 01 03 8F C3
```

## 8. 执行端实现检查表

- [ ] 支持小端序整数；
- [ ] CRC计算范围正确；
- [ ] 支持粘包、拆包和错误字节后的重新同步；
- [ ] 支持 `0x10` 动作缓存；
- [ ] 支持 `0x11` 开始执行；
- [ ] 支持 `0x20` 绝对、相对、归零和位置查询；
- [ ] 普通OK带被确认帧的SEQ；
- [ ] 位置回复包含真实XYZ和角度；
- [ ] 重复动作帧不会被重复缓存；
- [ ] 重复开始帧不会导致任务重新执行；
- [ ] CRC或字段错误时能请求重发；
- [ ] 运动过程不会阻塞串口接收状态机。
